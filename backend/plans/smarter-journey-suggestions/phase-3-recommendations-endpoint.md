# Phase 3 — "Picked for You" Recommendations Endpoint

**Effort:** ~2 days  
**Risk:** Medium — new endpoint + 1 new table for caching + AI generation for gap-fills

## What it does

Adds `GET /journeys/recommendations` — returns up to 6 journey recommendations personalised to the user, shown as a "Picked for You" section at the top of the journey tab.

Recommendations come from two sources:
1. **Catalogue matching** — score every existing journey (user's own + curated) against the interest profile from Phase 2. Free, instant.
2. **AI gap-fill** — if catalogue matching produces fewer than 3 strong matches, generate 1–2 new journeys on-demand using the interest profile topics. Budget-gated, same as `/explore`.

## New table: `journey_recommendations`

```sql
CREATE TABLE journey_recommendations (
    uid         text NOT NULL REFERENCES users(uid),
    generated_at timestamptz NOT NULL DEFAULT now(),
    journeys    jsonb NOT NULL DEFAULT '[]',  -- serialised Journey[]
    expires_at  timestamptz NOT NULL,
    PRIMARY KEY (uid)
);
```

Cache TTL: 24 hours. The endpoint checks this table first. If valid cache exists, returns it immediately (no AI cost, < 5ms). Cache is invalidated when the user completes a journey or makes a new explore search (so the recommendations stay fresh after meaningful activity).

## Endpoint

```
GET /api/v1/journeys/recommendations
Authorization: required
```

Response:

```json
{
  "recommendations": [
    {
      "journey": { ...Journey... },
      "reason": "Based on your interest in quantum physics",
      "reason_type": "interest"   // "interest" | "reinforce" | "level_up" | "explore_follow_up"
    }
  ],
  "cached": true,
  "generated_at": "2026-06-15T10:00:00Z"
}
```

## Scoring algorithm (catalogue matching)

For each candidate journey not already started or completed by the user:

```python
score = 0.0
for signal in profile.top_topics:
    tag_overlap = len({signal.topic} & set(journey.tags_lower))
    score += signal.weight * tag_overlap

# Bonus: difficulty match
if journey.difficulty == profile.preferred_difficulty:
    score += 0.3

# Bonus: curated journeys preferred over random user-generated ones
if journey.is_curated:
    score += 0.1

# Penalty: journey the user already owns (they explored it themselves)
if journey.uid == uid:
    score -= 0.5
```

Sort descending. Take top 6 with at least `score >= 0.3`. Below that threshold, trigger AI gap-fill.

## AI gap-fill (budget-gated)

If fewer than 3 catalogue matches score ≥ 0.3:

- Take the top 2 `TopicSignal` entries that have no catalogue match.
- Generate journeys using `generate_journey()` with a prompt shaped around the signal type:
  - `signal_type == "quiz_struggle"`: "Create a reinforcement journey on {topic} for a learner who is struggling with it at {difficulty} level"
  - `signal_type == "mastery_gap"`: same as `/explore` but explicitly build on what they know
  - `signal_type == "interest"`: same as a regular `/explore` question derived from the topic

Persist generated journeys to `journeys` table (same as `/explore`). Record usage via `record_usage`. Save full recommendation set to `journey_recommendations` cache.

## Cache invalidation triggers

These two events should clear the `journey_recommendations` row for the uid:

1. User completes a step in a new journey (write a DB trigger or handle in `progress.py` endpoint).
2. User makes a new `/explore` call (add `DELETE FROM journey_recommendations WHERE uid = %s` in `explore.py` after persisting the journey).

## Reason labels (frontend display)

| `reason_type` | Example label shown in UI |
|---|---|
| `interest` | "Based on your interest in machine learning" |
| `explore_follow_up` | "You explored quantum physics — go deeper" |
| `reinforce` | "Strengthen your understanding of DNA replication" |
| `level_up` | "Ready for the next level in music theory?" |

The `reason` string is generated by a simple template fill — no AI call needed.

## Frontend changes (document only — see frontend plan)

- Add "Picked for You" horizontal scroll section at the top of the journey tab, above "Continue Learning."
- Each card has a small reason chip below the title ("Based on your interest in…").
- Show a skeleton loader on first load since the first call may trigger AI generation.
- If the endpoint returns empty (brand-new user with no history), hide the section entirely — show it only once there's a signal.

## Acceptance criteria

- User with 3+ explore searches gets ≥ 3 recommendations, all journeys they haven't started.
- Reason strings are accurate to the signals used.
- Response is served from cache on second call (< 50 ms).
- Cache clears after a new `/explore` call and regenerates on next visit.
- A brand-new user (no journeys, no progress) gets an empty list (no crash, section hidden on frontend).
- AI generation is skipped if the user is over budget — returns catalogue matches only.
