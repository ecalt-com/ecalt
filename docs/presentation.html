01 · Product Overview

What ECALT Does

"Ask any question, get a personalised AI-powered learning journey. ECALT turns curiosity into capability for kids, families, and lifelong learners."

ECALT is a full-stack SaaS learning application. A user types any question or topic — the AI instantly generates a structured, multi-step Journey. Each step is an interactive AI conversation that teaches, tests, and tracks understanding. Progress is saved, gamified, and visualised as a Capability Passport.

Warm-Up Pre-caching

warm_journey_steps() pre-generates step content in the background immediately after a Journey is created. The next user request hits cache instead of waiting for LLM generation — dramatically reducing perceived latency. Cached content costs zero budget tokens on delivery.

04 · Authentication & Child Safety

Auth, Age Gates & Family Safety

🔑

Firebase Google Auth

Sign-in is exclusively via Google OAuth through Firebase Authentication. The backend verifies Firebase ID tokens on every protected request via verify_firebase_token(). Three auth guard levels: optional (anonymous allowed), required, and admin-only.

🔞

COPPA Age Gate

Birth year is collected at first sign-in via BirthYearGate. Users identified as under-13 trigger the full COPPA flow: Under13Block halts access, a parental consent email is dispatched automatically, and the account is suspended pending parent approval via ParentalConsentForm.

👨‍👩‍👧

Teen Consent Flow

Teen users (13–17) are routed through a separate consent confirmation screen (ConsentConfirm). Parental consent emails are sent via the email_service and tracked. The /users/consent-confirm endpoint handles parent click-through.

🌍

Geo Detection

Server-side country detection via Cloudflare headers with ip-api as fallback. Country code is used to select the correct payment gateway (Razorpay for India, Stripe elsewhere) and to pre-fill the WhatsApp country code selector.

🎭

Anonymous Sessions

Unauthenticated users can access Explore and Spark with a session ID for stateless rate-limiting. The get_optional_user() guard allows graceful degradation — no login wall on discovery features.

🔒

Admin Guard + Cache

A separate get_admin_user() dependency raises HTTP 403 for non-admins. The admin status check result is cached in-memory for 60 seconds per UID to avoid repeated DB lookups on every admin API call. Bootstrap script creates the first admin.

06 · Engagement & Notifications

Re-engagement & Notification System

📧

Email Notifications

Transactional emails sent via email_service. Includes parental consent emails, daily spark reminders, journey completion nudges, mind signature updates. One-click unsubscribe with signed token verification. Open tracking via pixel.

💚

WhatsApp Notifications

Twilio-powered WhatsApp messaging via whatsapp_service. Users opt in with a phone number + country code (auto-detected by geo). OTP-style confirmation flow. Users can opt out from Profile or via one-click link. WhatsApp nudge banner shown in the Learn page UI.

⏰

Background Scheduler

A persistent background task scheduler manages timed notifications. Enqueues: daily spark dispatch, journey-completion nudge, mind signature nudge. Respects per-user channel preferences and "not sent recently" guards to avoid spam. Preferred channel (email vs WhatsApp) selected per user.

Notification Pipeline

Scheduler enqueues event
can_send() — channel gate + recency guard
generate_copy() — AI-personalised message
send_email() or send_whatsapp()
track_open() — engagement event recorded

Cliffhanger Re-engagement

When a user starts an AI chat but doesn't complete it, the backend queues a "cliffhanger" notification via queue_cliffhanger(). This fires after a delay with an AI-written personalised message referencing the exact topic the user was learning — driving re-engagement without generic reminders.

User Notification Preferences

  • Per-channel opt-in/out (email, WhatsApp)
  • Preferences stored in notification_preferences table
  • PATCH endpoint for granular updates from Profile page
  • Admin can trigger test notifications for debugging

09 · Architecture & Infrastructure

System Architecture

Request Flow

User Browser (Vercel CDN)
React SPA — lazy routes + Context providers
api.ts → request() — attaches Firebase ID token
Vercel edge rewrite → Railway (HTTPS)
FastAPI — auth guard → route handler
Service layer → DB pool → Supabase Postgres
AI provider → SSE stream back to browser

Database Connection Pool

On startup, warm_pool() pre-creates all remaining connection slots in parallel so the first burst of requests doesn't experience cold connection overhead. The pool is a psycopg2 ThreadedConnectionPool sized for Railway's concurrency tier.

Error Handling

  • All HTTPExceptions logged with detail before returning to client
  • Catch-all unhandled exception handler returns JSON 500 with correct CORS headers
  • Frontend ErrorBoundary prevents white-screen crashes
  • Sentry captures frontend errors with stack traces

Performance Patterns

  • Optimistic UI — step toggles update instantly, sync in background
  • Lazy routes — every page code-split, loaded on first visit
  • Content cache — step content pre-warmed and served free
  • Admin cache — 60s in-memory cache on auth checks
  • Manual scroll restore — SPA preserves scroll position across navigation
10 · Compliance & Security

Regulatory Compliance & Security

🇺🇸

COPPA Compliance

Full Children's Online Privacy Protection Act implementation:

  • Birth year collected at account creation via BirthYearGate
  • Under-13 users blocked from app content immediately (Under13Block)
  • Parental consent email sent automatically via send_parental_consent_email()
  • Consent stored and verified before account activation
  • Teen (13–17) flow routes through additional consent confirmation
  • Unit test suite: test_age_verification.py
🇪🇺

GDPR Data Rights

Full General Data Protection Regulation support:

  • Right to export — export_account() packages all user data
  • Right to erasure — delete_account() hard-deletes all records
  • Privacy Policy, Terms of Service, and Parents pages published
  • Unit test suite: test_gdpr.py
  • Email unsubscribe uses signed tokens (not user IDs) to prevent enumeration
🔐

API Security

  • All endpoints protected by Firebase ID token verification
  • Admin endpoints gated by separate get_admin_user() dependency
  • Chat injection defense pattern implemented in chat_service
  • Stripe webhook signature verified before processing
  • Razorpay webhook HMAC signature verification
  • Razorpay payment signature verified before subscription activation
🏗️

Database Security

  • Supabase Row-Level Security (RLS) policies enforced at DB layer
  • All queries use parameterised statements — no string interpolation
  • Connection pool credentials loaded from environment variables
  • Sensitive fields (tokens, keys) never logged
  • Coupon soft-delete preserves audit trail without exposing deleted data
